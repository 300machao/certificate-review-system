# Codex 长期协作工作流

## 1. 目标

本工作流把正在使用的本机业务系统拆分为可审查、可恢复的小变更，避免在一个长期对话中持续直接修改正式项目。源码回滚使用本地私有 Git；正式数据恢复使用独立备份，两者不能互相替代。

## 2. 任务分层

每个 Codex 任务只负责一个明确结果，例如“修复一项规则门禁”“增加一项迁移测试”或“完善一份运维文档”。任务开始时必须写明：

- 业务目标和企业接收方视角；
- 允许修改的文件；
- 明确不在范围内的正式数据、模型、部署和平台写回；
- 是否涉及 schema、依赖、网络、费用或浏览器行为；
- 自动测试、浏览器验收和回滚标准。

没有这些边界时先做只读预检，不进入实施。

## 3. 分支、提交和 worktree

- `main` 保存经过验收的本地基线和后续稳定点。
- 基线标签用于标识初始化时的可回退源码状态；标签不包含也不能恢复 `data/`。
- 小型低风险变更使用独立分支；复杂、并行或数据库相关变更使用独立 Git worktree。
- 不得在包含未归属用户修改的工作区执行 reset、clean、checkout 覆盖或批量格式化。
- 每个提交只包含一个逻辑变化。提交前必须查看 staged 文件和 diff，确认没有正式数据、日志、原件、密钥或未经脱敏材料。
- 本项目默认没有远程。新增远程、推送、PR、部署或公开发布都需要单独授权。

## 4. 变更生命周期

1. 从 `docs/changes/TEMPLATE.md` 建立变更记录。
2. 完成只读现状检查，列出证据和假设。
3. 对高风险决定新增或更新 `docs/decisions/` 下的 ADR。
4. 建立独立分支或 worktree，并记录基线提交。
5. 按最小范围实现；数据库变更必须同时提交迁移、旧库兼容测试和回滚说明。
6. 在隔离环境用临时数据、禁用模型运行离线测试和前端语法检查。
7. 在临时数据目录、空闲回环端口上完成浏览器可见验收。
8. 核对正式 `data/` 未变化、Git 暂存清单安全、文档与代码一致。
9. 提交后记录实际提交、测试结果、未完成项和回滚方法。

## 5. 安全验证会话

自动测试必须使用项目虚拟环境。PowerShell 会话先执行：

```powershell
$env:CERT_MODEL_MODE = "disabled"
$env:CERT_DATA_DIR = Join-Path ([System.IO.Path]::GetTempPath()) ("certificate-review-tests-" + [guid]::NewGuid().ToString("N"))
& .\.venv\Scripts\python.exe -m pytest -q
node --check .\static\app.js
```

必须保留 `tests/conftest.py` 在导入 API 前设置临时数据和禁用模型的门禁。不要用 `python -c "import app.api"` 检查正式服务；该导入会打开数据库并可能执行恢复写入。

浏览器可见验收另开受控会话：使用新的临时 `CERT_DATA_DIR`、`CERT_MODEL_MODE=disabled`、合成或已确认脱敏的输入，只绑定 `127.0.0.1` 的空闲端口。需要人工看到并核对至少以下路径：

- 首页可加载且显示本地/模型禁用边界；
- 导入脱敏批次并看到进度；
- 打开证据和原件预览；
- 缺证据时保持 `UNCERTAIN`，真实性保持 `UNVERIFIED`；
- 人工决定产生新版本且机器原始结果仍可见；
- 导出结果可读且不泄露密钥或对象绝对路径。

## 6. 数据库变更专用门禁

- 在唯一的新备份通过文件数、总字节、SQLite 完整性和审计链核验前，不开始迁移开发。
- 只对正式库的副本和合成旧版本夹具运行迁移。
- 迁移必须幂等、可检测、可中止；失败不得留下“半迁移成功”的正式结论。
- 必须同时验证旧库首次打开、已迁移库重复打开、回滚恢复和浏览器原件路径。
- 不得用手工 SQL、全局字符串替换或直接编辑 JSON 绕过审计链和业务完整性。
- schema v2 绝对路径迁移受 `docs/decisions/0002-absolute-path-migration-gate.md` 约束。

## 7. 回滚模型

代码回滚：停止临时测试服务，确认没有正式数据写入，然后切回已知提交或基线标签。对共享工作区不得使用破坏性 Git 命令；优先新分支、revert 或重新建立 worktree。

数据回滚：Git 不参与。停止网站，保留当前故障数据为新的只读诊断副本，再从已经核验的完整 `data/` 备份恢复到隔离位置。通过 SQLite、审计链、对象哈希和浏览器路径验证后，才可按获批切换方案替换正式数据。

## 8. 状态报告格式

每次交付必须明确区分：

- 已完成并有证据；
- 已执行但未通过；
- 未执行；
- 因授权、数据、模型或外部依赖而阻塞。

最终报告至少包含修改文件、提交/标签、测试结果、浏览器证据、正式数据变化检查、备份位置引用、风险、未完成项和回滚步骤。不得把历史缓存、旧测试结果或“进程已启动”描述为本轮验收完成。
