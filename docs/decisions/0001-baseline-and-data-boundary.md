# ADR 0001：本地 Git 基线与正式数据边界

- 状态：已接受
- 日期：2026-08-18
- 决策范围：项目治理和版本控制边界

## 背景

该项目已经承载真实数据库、证书原件、审计记录和当前 Windows 用户保护的 DPAPI 凭据。过去以本机目录直接迭代，缺少统一项目规则、可审查的变更记录和明确的代码回滚点。直接把整个目录纳入 Git 会泄露业务信息，并错误地把 Git 当成数据库备份。

## 决策

1. 只建立本地私有 Git 仓库，不配置远程、不推送、不部署。
2. `main` 保存通过验收的源码与治理文档基线，并使用带说明的基线标签标识初始化点。
3. `data/`、数据库及 WAL/SHM、证书原件、DPAPI 密文、日志、运行标记和未经脱敏业务材料永不进入 Git。
4. 根目录 `acceptance-result.*` 与 `validation/` 在完成内容审查并证明完全脱敏前也排除 Git；文件名或“验证材料”标签不能作为可提交依据。
5. 正式数据使用唯一、完整、核验过的 `data/` 备份恢复。Git 只恢复受控源码和文档。
6. 每个变更使用独立任务和分支；复杂、高风险或并行工作使用 Git worktree。
7. 所有代理遵守根 `AGENTS.md`，以变更模板记录范围、验证和回滚。

## 理由

- 源码变更适合用提交、标签、分支和 diff 审查；正式数据库和原件需要一致性快照、哈希与审计链核验。
- 本地仓库避免未经授权的外传，同时提供可回退的代码历史。
- 先建立排除边界再提交，可以避免敏感文件进入任何历史提交；仅在后来删除文件不能消除历史泄露。

## 结果

正面结果：代码和文档获得明确基线，后续任务可隔离并审查；正式数据与源码回滚责任分离。

代价和限制：Git 标签不能证明数据备份成功；worktree 也不能包含正式 `data/`。任何需要真实数据的排障必须单独授权，并优先使用受保护副本或脱敏夹具。

## 验收

- 初始化提交前审查完整 staged 清单。
- Git 对象中不存在正式数据、原件、密钥、日志或未经脱敏材料。
- `main` 和基线标签均只指向批准的源码/文档基线。
- `git status` 清楚区分受控文件、被忽略正式数据和未纳入的敏感材料。
- 已记录独立数据备份及恢复方法，但不把业务备份清单提交 Git。

## 回退

若初始化提交内容越界，在没有推送和后续依赖前停止使用该仓库，保留证据并按批准方案重建仅含安全文件的仓库。不得通过删除正式源文件或运行 `git clean` 修复越界。正式数据保持原位，并从数据备份体系独立恢复。
