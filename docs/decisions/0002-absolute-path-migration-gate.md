# ADR 0002：schema v2 绝对路径兼容迁移门禁

- 状态：已接受
- 日期：2026-08-18
- 决策范围：移动项目、恢复到新路径和数据库路径迁移

## 背景

当前数据库代码的 `SCHEMA_VERSION` 为 2。对象存储根在导入时执行绝对路径解析，结果至少写入两个位置：

1. `certificates.storage_path`；
2. `certificates.metadata_json` 中的 `review.metadata.stored_path`。

服务重载、原件预览和重试直接读取 `storage_path`，并把解析后的路径与当前 `data/storage/objects` 做边界比较。移动项目根或数据目录后，旧绝对路径可能失效，或即使文件存在也因不属于当前对象根而被拒绝。

冻结台账或输入证据可能带有用户提供的 `local_path`、`archive_path` 等字段。它们目前不被认定为对象取回的主契约，但在迁移前仍须盘点实际库值和使用代码，不能假定无影响。

## 决策

在兼容迁移完成并通过全部门禁前：

- 不移动、不重命名项目根或正式 `data/`；
- 不把正式库恢复到不同根后直接启动；
- 不直接编辑 SQLite、JSON 字符串或审计事件来替换路径；
- 不以目录联接、符号链接或长期保留旧路径作为迁移完成的证明。

本 ADR 接受“先建立可验证迁移，再允许移动”的门禁，但不在此决定最终采用相对对象键、重定位表或其他持久化设计。最终设计需单独变更记录和评审。

## 迁移前必须完成

1. 网站和桌面程序停止，完整 `data/` 已复制到唯一新备份。
2. 备份通过文件数、总字节、SHA-256、SQLite、外键、审计链、业务完整性和对象关联核验。
3. 对正式库副本盘点所有路径形态，包括结构化列、嵌套 JSON、冻结台账值和审计载荷；结果存放在受保护位置，不提交业务值。
4. 明确旧根、新根、允许转换的严格子路径和拒绝条件。
5. 建立代表真实旧 schema v2 结构的脱敏夹具和合成库。
6. 决定 schema 版本推进、旧库首次打开行为、失败原子性和回滚契约。

## 迁移实现门禁

迁移必须同时满足：

- 只在旧对象根的严格后代路径上转换，拒绝越界、空路径、网络路径、链接和无法解析路径；
- 同步处理 `certificates.storage_path` 与 `review.metadata.stored_path`，并检测二者原有冲突；
- 对每个对象验证存在性、可读性、大小和内容 SHA-256；
- 盘点用户输入路径，但不盲目重写证据字段；
- 使用事务，任一记录失败时不留下半迁移状态；
- 幂等：已迁移数据库重复打开不会再次改变业务行或审计链；
- 保留机器原始结果、人工版本和审计历史；迁移证据以追加事件或经评审的完整性机制记录，不伪造旧事件；
- 不通过应用 API 导入正式库做探测，不运行 backfill，不调用模型；
- 提供明确的旧库兼容和恢复到原路径方案。

不得用全局字符串替换，因为 JSON 中可能存在证据文本、用户输入路径或相似前缀；也不得绕过业务完整性后再重新“基线化”来掩盖直接修改。

## 测试矩阵

- 全新库创建；
- 未迁移 schema v2 副本首次迁移；
- 迁移中途异常和事务回滚；
- 已迁移库重复打开；
- 主字段与 JSON 副本一致、缺失和冲突三种情况；
- 旧根前缀相似但并非其子路径；
- 对象缺失、哈希不一致、链接和越界路径；
- 冻结台账含用户输入路径但不应自动重写；
- 审计链和业务完整性在迁移前后均可解释且通过；
- 回滚到完整旧备份；
- 临时数据、模型禁用、仅回环条件下的浏览器原件预览、详情、重试前置读取和导出。

## 允许移动的验收标准

只有以下项目全部有本轮证据时，项目移动门禁才可解除：

1. 迁移测试和全量离线测试通过；
2. 在正式库副本上迁移成功，所有对象关联和哈希通过；
3. SQLite 完整性、外键、审计链和业务完整性通过；
4. 新根不需要旧路径、目录联接或符号链接；
5. 浏览器可见业务路径能打开原件、显示历史机器结果和人工版本并安全导出；
6. 正式旧路径和完整备份保持不动，可执行反向切换；
7. 迁移正式数据和移动项目获得单独明确授权。

## 回滚

迁移失败或验收不完整时停止新根服务，保留失败副本用于只读诊断，不二次覆盖。重新使用未修改的旧项目根和已验证的完整旧 `data/`；重新核对进程、SQLite、审计链、对象关联和浏览器路径。Git 回滚不能恢复数据库路径字段，必须使用数据备份回滚。

## 相关未决风险

应用同时报告 `1.1.0` 和 `2.0.0`。该版本冲突与路径迁移分别处理；本 ADR 不授权统一应用版本，也不能用其中任一版本号推断 schema 兼容性。
