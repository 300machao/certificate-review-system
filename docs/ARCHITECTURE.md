# 架构说明

## 1. 系统定位

本系统服务于企业接收外检计量证书后的信息一致性审核和计量确认辅助，不是发证机构系统，也不是官方真实性验证平台。系统必须把以下三类结论分开保存和展示：

1. 证书信息与企业冻结台账、二维码和版面提取结果是否一致；
2. 证书结果是否满足企业实际用途和计量要求；
3. 是否已有发证机构官方查询、电子签章或其他权威真实性证据。

在未接入官方验真时，真实性状态始终为 `UNVERIFIED`。模型只参与证据提取和解释，不能代替台账、检定/校准数据、官方查询或人工责任决定。

## 2. 运行形态

系统有三种入口：

- 浏览器网站：`启动网站.cmd` 调用 `start.ps1`，默认用 Uvicorn 在 `127.0.0.1:8766` 提供 FastAPI 和静态前端。
- 桌面应用：`start_desktop.ps1` 调用 `pythonw desktop_main.pyw`，pywebview 创建窗口，并在随机回环端口承载同一 FastAPI 应用。
- 离线 CLI：`app/cli.py` 可批量处理输入并导出结果；该入口会写数据库和输出文件，不是只读诊断工具。

浏览器和桌面入口都只能监听回环地址。`start.ps1` 保留 `HostAddress` 参数用于兼容旧入口，但会拒绝除 `127.0.0.1` 以外的值；健康检查通过后，它记录真正拥有监听端口的 Python PID及其 `.venv` 启动器 PID。`stop.ps1` 会复核端口、命令和父子关系后先停止监听进程。桌面壳绑定 `127.0.0.1` 的随机端口。此门禁仍须由启动脚本测试和实际监听检查共同验收。

导入 `app.api` 会立即创建 `BatchReviewService`。服务构造过程会解析正式数据目录、创建目录、打开 SQLite、初始化 schema，并可能把中断中的任务恢复为失败状态。因此不得通过导入正式 API 来做只读健康探测。

## 3. 主要组件

| 组件 | 位置 | 责任 |
|---|---|---|
| Web/API | `app/api.py` | HTTP 路由、安全响应头、上传、复核、导出和模型设置接口 |
| 业务编排 | `app/service.py` | 批次状态、证据处理、规则与模型路由、人工复核、导出 |
| 持久化 | `app/database.py` | SQLite schema、事务、外键、WAL、审计链和业务完整性 |
| 导入与对象存储 | `app/ingest.py` | 文件/ZIP/清单门禁、内容哈希、去重和对象提交 |
| 提取器 | `app/extractors/` | PDF、图像、OCR 和二维码证据提取 |
| 规则 | `app/rules/` | 字段规范化、三方比较和确定性判定 |
| 模型适配 | `app/providers.py`、`app/vision.py`、`app/semantic.py` | 可选视觉提取、文本解释和独立仲裁 |
| 本地设置 | `app/model_settings.py` | 非敏感模型配置和当前 Windows 用户 DPAPI 密文 |
| 前端 | `static/` | 无构建步骤的 HTML、CSS 和 JavaScript |
| 桌面壳 | `app/desktop.py` | 回环服务、pywebview 窗口和受限导出桥 |

## 4. 数据流

1. 用户提交 PDF、图片、目录或安全 ZIP，并可同时提供冻结台账清单。
2. 导入层验证文件类型、魔数、大小、ZIP 路径和解压限制，在临时区完成验证后才提交对象。
3. 原件按 SHA-256 内容地址存入 `data/storage/objects/`；相同内容可复用对象，但业务记录保持独立。
4. 本地 PDF/图像/二维码提取产生带来源的证据；冻结台账作为独立快照保存。
5. 规则引擎比较二维码、版面提取和冻结台账。缺少关键证据时保持不确定并进入人工流程。
6. 只有在明确启用且凭据有效时才允许模型参与；模型失败、低置信或冲突不能提升为自动通过。
7. 人工决定新增版本，不覆盖机器原始提取、规则结果或模型决定。
8. 业务变更和人工处置写入追加式 SHA-256 前序哈希审计链。

## 5. 持久化边界

`data/` 是一个不可拆分的正式数据单元：

- `certificate-review.sqlite3` 及同名 `-wal`、`-shm`：业务数据库及 SQLite WAL 状态；
- `storage/objects/`：按内容哈希保存的证书原件对象；
- `settings/model-providers.json`：非密钥模型设置；
- `settings/model-api-keys.dpapi.json`：当前 Windows 用户保护的 DPAPI 密文；
- `validation/`：运行生成的验证材料；
- 运行标记和日志。

不得只备份 SQLite 主文件，也不得只备份对象目录。代码和 Git 历史不能恢复正式数据；数据恢复必须使用经过核验的完整 `data/` 备份。

## 6. schema v2 绝对路径风险

当前数据库代码的 `SCHEMA_VERSION` 为 2。导入层先对对象根执行 `resolve()`，再把对象路径字符串写入：

- `certificates.storage_path`；
- `certificates.metadata_json` 内 `review.metadata.stored_path` 的副本。

服务重载、原件预览和重试会直接把这些字段转换为 `Path`，并要求解析后的路径仍位于当前 `data/storage/objects` 下。移动项目根或 `data/` 后，旧绝对路径可能不存在，或因边界检查而拒绝读取。因此在兼容迁移完成前禁止移动或重命名项目。

冻结台账或输入证据中还可能由用户提供 `local_path`、`archive_path` 等路径字段；它们不是当前对象取回主契约，但迁移前必须逐字段盘点，不能假定无影响。迁移门禁见 `docs/decisions/0002-absolute-path-migration-gate.md`。

## 7. 信任和网络边界

- 系统是本机单用户应用，当前没有登录与多租户隔离，不适合局域网或公网暴露。
- GET 配置状态不应产生外部调用；模型连接测试和实际模型请求必须由显式操作触发，并可能产生费用。
- 质检数智平台只可作为外部证据来源；本项目不得新增写回、自动处置或凭据复用。
- DPAPI 保护的是密钥静态存储，不替代文件权限、备份隔离或同用户访问控制。
- 原件、台账、审计记录和人工决定是敏感业务信息，不进入 Git、日志样例或公开问题描述。

## 8. 版本与可重复性风险

当前存在未决版本冲突：Python 包、桌面桥和 Windows 文件元数据报告 `1.1.0`，FastAPI 元数据及 capabilities 报告 `2.0.0`。在单一版本来源方案获批前不得自行统一、改写或据此发布版本。

当前依赖以范围约束为主，历史运行依赖 PATH 中的全局 Python。`.python-version` 记录基线观察到的 Python 3.12.4，但依赖锁文件和隔离环境仍须由单独、可验证的变更建立。

## 9. 验收层次

一次变更的最低验收顺序是：

1. 静态审查和敏感文件边界检查；
2. 临时数据、真实模型禁用条件下的全量离线测试；
3. `node --check static/app.js` 前端语法检查；
4. 仅回环监听检查；
5. 使用脱敏夹具完成浏览器可见的导入、证据查看、人工版本和导出路径；
6. 证明正式 `data/` 未改变，并给出代码回滚与数据恢复方案。

仅有 API 单元测试或 HTTP 200 不能替代第 5 项。
