# 正式数据备份与恢复

## 1. 目的和边界

本文用于完整保护本机正式 `data/`。备份、恢复和迁移是三个不同动作：

- 备份：保留源，只复制到唯一的新目录并验证；
- 恢复：从已验证备份建立新的候选数据目录，验收后再按批准方案切换；
- 迁移：改变 schema、字段内容或路径契约，必须有独立迁移测试和回滚。

任何 Git 操作都不能代替数据备份。不得把备份目录放入项目 Git 工作树，也不得提交备份清单中包含的业务文件名、路径或哈希到仓库。

## 2. 完整备份范围

必须复制 `data/` 整体，包括隐藏文件和当时存在的全部内容：

- `certificate-review.sqlite3`；
- `certificate-review.sqlite3-wal`；
- `certificate-review.sqlite3-shm`；
- `storage/objects/` 全部对象和目录层级；
- `settings/` 中非敏感配置与 DPAPI 密文；
- `validation/`、日志、运行标记及其他数据文件。

即使网站已经正常停止，也不得预先删除 WAL、SHM、日志或陈旧 PID 标记来“整理备份”。如果 WAL 或 SHM 在备份时不存在，记录其不存在；如果存在，必须原样纳入。不得只复制 SQLite 主文件后宣称备份完成。

## 3. 备份前门禁

1. 获得本次备份授权和维护窗口。
2. 记录项目根、正式数据根、当前时间和操作者 Windows 用户；不得记录密钥值。
3. 从进程、命令行和监听端口三方面确认浏览器网站、桌面壳和打包程序已停止。
4. 将 `server.pid` 只视为线索。PID 缺失、复用或标记陈旧都不能证明服务状态。
5. 确认没有导入、backfill、retry、模型任务、数据库查看器或其他写入者。
6. 解析源目录和备份父目录的绝对路径；确认目标位于批准的备份父目录内，且不是项目根、`data/` 内部、符号链接或重解析点。
7. 生成带 UTC/本地时间和随机后缀的唯一目标名；目标已存在时立即停止，绝不覆盖或合并旧备份。

如果无法排除活跃写入者，停止操作并重新安排维护窗口，不得依赖强制复制或锁绕过。

## 4. 复制与核验

复制必须使用保留源的单向复制，并对源和目标分别生成核验结果。完成标准至少包括：

1. 顶层清单一致；
2. 递归文件数一致；
3. 递归总字节一致；
4. 每个文件可读；
5. 每个文件的 SHA-256 与源一致；
6. SQLite 主文件、WAL、SHM 的存在状态和字节数已记录；
7. 对备份副本以只读方式运行 `PRAGMA quick_check`、`PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`；
8. 使用不会初始化或迁移数据库的只读审计验证器核对前序哈希链和业务完整性；
9. 对数据库引用的每个对象路径/对象键核对目标对象存在、可读、大小和 SHA-256；
10. 核验报告保存在受保护的运维位置，不把业务清单提交 Git。

不得通过导入 `app.api` 验证备份；这会构造服务并可能写入。也不得对唯一备份副本执行可能 checkpoint、迁移或改变 `PRAGMA user_version` 的工具。需要应用级验证时，先从备份再复制一个唯一的验证工作副本。

审计链、业务完整性或对象关联任一项未验证，状态只能是“复制完成、业务恢复能力未确认”，不能写成“备份成功”。

## 5. DPAPI 边界

`data/settings/model-api-keys.dpapi.json` 由 Windows DPAPI 绑定到保存它的用户上下文。完整备份必须包含该密文，以便同一用户恢复；但：

- 不得解密、打印、散列后公开或提交该文件；
- 换电脑、换 Windows 账户或用户配置损坏时，不能假定密文可用；
- 跨账户恢复应在获批后重新输入已轮换的凭据，而不是复制明文或绕过 DPAPI；
- 恢复验收默认禁用模型，不以连接测试验证 DPAPI，也不产生模型费用。

## 6. 恢复流程

1. 获得明确恢复授权，说明目标时间点、原因和可接受的数据损失窗口。
2. 停止所有应用入口和写入者；再次确认仅回环端口无监听。
3. 先把当前故障 `data/` 复制到新的只读诊断备份，不覆盖原备份。
4. 把选定备份完整复制到项目外的唯一恢复暂存目录。
5. 在恢复暂存副本上重复文件数、总字节、SHA-256、SQLite、外键、审计链和对象关联核验。
6. 检查 schema 版本和绝对路径。schema v2 备份包含旧项目根绝对路径时，不得直接移动到新根运行；先满足路径迁移 ADR。
7. 使用 `CERT_MODEL_MODE=disabled`，在隔离验证副本和仅回环端口启动，完成浏览器可见的批次列表、证据详情、原件预览、人工版本和导出检查。
8. 记录正式切换方案和反向切换点。只有所有门禁通过后，才在另一次明确批准下切换正式数据目录。
9. 切换后再次验证，不删除旧正式目录或任何备份。

恢复不得采用“直接把若干数据库文件覆盖到正在运行的 `data/`”的方式。文件被锁、复制失败、路径不明或核验不一致时立即停止，不使用更强删除、强制替换或跳过验证的方式重试。

## 7. 绝对路径与迁移

schema v2 的 `certificates.storage_path` 和 `metadata_json.review.metadata.stored_path` 保存对象绝对路径。恢复到原路径仍需核对边界和对象哈希；恢复到不同路径则必须先运行获批、可回滚的兼容迁移。

迁移不得直接全局替换字符串。它必须：

- 只在旧根目录的严格子路径上转换；
- 拒绝越界、缺失、链接和哈希不匹配对象；
- 同步处理主字段和 JSON 副本；
- 盘点冻结台账中可能存在的用户输入路径，但不把它们误当对象主契约；
- 保留并扩展审计证据，不覆盖机器原始结果；
- 对旧库、迁移库、重复执行和回滚恢复分别测试；
- 通过浏览器原件预览和重试前置读取验证。

完整门禁见 `docs/decisions/0002-absolute-path-migration-gate.md`。
